# 数据与存储

## 目录结构

```text
data/
├── projects/                 # 故事项目 JSON
├── books/<book_id>/          # 导入书籍
│   ├── book.json             # 元数据与分析档案
│   ├── chapters.json         # 章节索引
│   └── chapters/*.txt        # 按章正文
├── versions/                 # 项目和书籍版本快照
├── embedded-vault.json       # 内嵌 Vault 模式
├── rhine-vault-core.db       # 桌面默认 Vault Core
└── llm-config.json           # 本机模型配置
```

Android 使用 App 私有数据目录，结构与源码运行环境对应，但路径由 Android 管理。

## 持久化策略

| 数据 | 策略 | 说明 |
| --- | --- | --- |
| 故事项目 | 单项目 JSON、临时文件替换 | 保存简单；高并发写入仍需项目级锁 |
| 导入书籍 | 元数据/索引 JSON + 每章 TXT | 避免百万字全文反复序列化 |
| 书籍写入 | `RLock` + 原子替换 | 保护同进程内并发访问 |
| 版本 | 独立快照目录 | Agent 写入和恢复前生成版本 |
| Vault Core | SQLite | 适合桌面本机的结构化知识数据 |
| 内嵌 Vault | JSON + `RLock` | 适合 Android 与低依赖部署 |
| 分析状态 | 书籍目录内持久化 | 支持暂停识别、哈希缓存和续跑 |

## 版本与恢复

项目和书籍的 Agent 修改会在执行前自动提交快照。恢复某个快照时，系统先记录当前状态，再覆盖目标实体。外部 Agent 应保存执行响应中的 `snapshot`，并在界面提供可见的恢复入口。

快照不是完整备份：模型设置、独立 Vault 连接、刚创建的实体和部分系统状态不一定包含在项目/书籍版本中。迁移或升级前应使用完整 ZIP 备份。

## 长篇分析数据

分析器将章节切为片段，先生成局部结果，再树状汇总。节点保存输入内容哈希；内容和分析模式未变化时可以复用结果。应用重启后，残留的运行状态会被识别为暂停，允许继续处理。

## 数据兼容策略

当前软件尚未正式发布，不需要维持旧版兼容层。数据结构变更应采用显式 `schema_version` 和一次性迁移，而不是在读取路径长期堆叠兼容分支。迁移必须满足：

1. 迁移前自动备份。
2. 迁移可重复检测，不能重复破坏数据。
3. 失败时保留原文件并给出可操作错误。
4. 迁移逻辑和代表性旧数据样例纳入测试。
