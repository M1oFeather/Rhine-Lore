# 未来路线

路线以公开 Beta 的工程门槛为目标，不保留尚未发布版本的长期兼容层。每一阶段都应使用显式数据迁移和可回滚备份。

## 阶段 0：基线冻结

目标：把当前行为变成可验证契约，避免继续扩展时失去基线。

- 为 `/lore-api` 建立 v1 路由与统一响应/错误模型。
- 生成 OpenAPI、Agent 工具 JSON Schema 和能力发现端点。
- 建立数据 `schema_version`、启动迁移器和迁移前备份。
- 把版本号统一检查加入 CI。
- 固化三条 E2E：导入并阅读、对话确认并恢复、长篇分析并转工作台。

退出标准：接口契约测试、数据迁移测试和三条 E2E 都可在 CI 重复通过。

## 阶段 1：安全与一致性

目标：达到受邀测试和可信局域网使用门槛。

- 所有 Lore 接口启用本机会话或 Bearer Token。
- 默认精确 CORS Origin，局域网模式显式开启并展示风险。
- 写操作使用确认 nonce，绑定用户、工具、参数哈希和过期时间。
- 非幂等写入支持 `Idempotency-Key`。
- 项目/书籍写入统一使用实体锁、修订号和冲突响应。
- 增加结构化审计日志和一键导出诊断包，默认脱敏。

退出标准：跨源未授权请求失败；重复请求不产生重复实体；并发写入不会静默覆盖。

## 阶段 2：模块化与测试

目标：降低页面和接口继续演化的回归成本。

- 将 Vue 主界面按首页、对话、阅读器、工作台、资料库、设置拆分为路由页。
- 提取阅读设置、分支树、确认动作、导入向导等领域组件和 composable。
- 将样式拆为 token、布局、组件和页面层，删除冲突选择器。
- 将 Python 路由拆为 handler/service/repository，输入只接受 Schema 校验后的对象。
- 增加前端单测、Playwright 桌面/手机视觉回归和 API 合约测试。

退出标准：关键页面能独立测试；样式修改不会依赖全局覆盖顺序；大型文件进入可控规模。

## 阶段 3：长篇理解与分支产品化

目标：把最有差异化的能力做成可靠日常工作流。

- 分析任务支持持久队列、并发限制、预算预估、暂停和逐层重试。
- 每条人物、势力、地点、关系和事实保留章节来源与置信度。
- 建立同名实体合并、冲突事实对照和用户裁决流程。
- 分支树显示来源位置、生成指导、变更摘要、继承上下文和工作台状态。
- 从选定路径导入工作台时保留来源映射，后续可追溯到原章节。
- 评估使用结构化模型 tool calling，替代文本 JSON 提取。

退出标准：百万字作品可中断恢复；用户能解释每个提取事实和工作台实体来自哪里。

## 阶段 4：Vault 与 Agent 生态

目标：在核心体验稳定后开放受控扩展。

- 发布轻量 Agent SDK，并提供 OpenAI function schema 与 MCP 适配器。
- 支持独立 Vault 配置档案、连接测试、权限提示和安全凭据存储。
- 资料检索返回证据与版本，创作引用可回溯。
- 建立受权限控制的插件能力清单，不允许插件默认获得全部写权限。
- 评估可选端到端加密同步；单机模式保持一等公民。

## 不建议近期投入

- 通用聊天机器人和与写作无关的 Agent 工具。
- 在单机 JSON API 上直接叠加多人实时协作。
- 没有权限模型前的公网 Vault 或插件市场。
- 为未发布数据格式长期保留多套兼容读取路径。
- 只增加模型调用量、却不提供证据、预算和恢复能力的“全书一键智能化”。

## 建议指标

| 指标 | 目标 |
| --- | --- |
| TXT 导入编码/拆章一次成功率 | 可按编码、语言、书籍规模分组观察 |
| 首次导入到开始阅读时间 | 大文件也保持可感知进度和可取消 |
| 分支生成到保留的转化率 | 衡量续写是否真正有用 |
| 分支转工作台成功率 | 衡量核心闭环 |
| Agent 动作确认/拒绝/恢复率 | 发现工具建议质量与误操作风险 |
| 长篇分析缓存命中与恢复成功率 | 衡量规模化能力 |
| 数据迁移和恢复成功率 | 发布门槛，应接近 100% |
| 关键页面移动端视觉回归 | 每次发布必须通过 |
