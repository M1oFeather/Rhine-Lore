# v0.2.0 Release Notes

发布日期：2026-08-15

v0.2.0 把 Rhine-Lore 从功能集合推进为一套连贯的本地优先小说工作台。用户可以从空白故事、内置奇幻演示或外部 TXT 开始，在阅读器中理解长篇、从任意位置建立分支，再把人物、势力、地点与关系带入工作台继续创作。

## 核心链路

```text
导入 TXT -> 编码检测 -> 拆卷/拆章 -> 阅读 -> 长篇分析
                                      -> 任意位置分支 -> 分支树
                                      -> 提取人物/势力/地图 -> 工作台

工作台 -> 对话提出修改 -> 用户确认 -> 自动快照 -> 写入 -> 版本恢复

资料草稿 -> 送审 -> 入库 -> 检索引用 -> 对话/正文创作
```

## 主要变化

### 阅读与长篇小说

- TXT 导入支持编码自动检测、预览与手动重选，覆盖 UTF-8、GBK、GB18030、Big5 和 UTF-16 等常见来源。
- 正文按章存储和加载，避免百万字小说反复整体读写。
- 阅读器支持滚动/翻页、目录、搜索、书签、主题、字号、行距、页宽和阅读进度。
- 卷名与章节标题使用独立标题页，桌面和手机视口分别优化正文宽度与安全区。
- 长篇分析使用分片、树状汇总和内容哈希缓存，任务状态可持久化并在重启后继续。

### 分支与创作工作台

- 阅读器和工作模式都可以从选区、段落、光标或当前阅读位置创建 AI 分支。
- 可视化分支树展示父子路径、生成方向、当前位置和完整路径。
- 选定的小说与分支可以转换成工作台项目，并带入人物、势力、地点和地图数据。
- 项目正文、人物、设定和主要书籍结构变更在 Agent 执行前自动创建版本快照。

### 对话与资料库

- 对话页形成独立产品布局，支持项目、TXT 和知识附件。
- 只读 Agent 工具可在对话循环中自动执行，写工具作为待确认动作返回。
- 对话内容可以提取为结构化知识草稿，再经过送审与入库流程。
- Lore 自动准备默认 Rhine-Vault Core，也可以连接独立 Vault；可选安装 Vault Web 并从设置页跳转。

### 初始演示

- 空数据目录首次启动会创建原创哥特奇幻项目《灰烬月冠》。
- 演示包含三章正文、五名角色、八项世界设定、七个地图地点、文风约束和三个待处理伏笔。
- 新建故事弹窗可以在“空白故事”和“奇幻演示”之间切换，已有项目不会被覆盖。

### 界面与移动端

- 首页改为故事引导台，以小型故事卡选择项目，不在首页堆叠人物和世界编辑器。
- 顶栏持续展示当前项目、模式切换与后端连接状态，删除重复设置入口。
- 对话、阅读、资料库、设置、故事档案、地图和演化页面重新整理为现代应用布局。
- 修复页面底部空白、固定区域冲突、手机软键盘遮挡和 Android 返回键行为。
- 更新应用标记与机能简约图标系统。

## Agent 接入边界

v0.2.0 提供 `/lore-api/llm/chat`、`/lore-api/llm/chat/stream` 与 `/lore-api/agent/execute`，并在文档中列出全部 27 个内置工具。当前服务仍按单用户、本机产品设计：没有用户鉴权，写操作确认尚未由服务端 nonce 强制执行，不应直接暴露到公网。

- 文档：`mkdocs build --strict` 通过。

## 升级说明

v0.2.0 不主动覆盖已有项目。首次启动前建议导出完整 ZIP 备份。模型 API Key 不包含在备份中，迁移设备后需要重新配置。

当前软件尚未正式公开发布，不提供长期旧数据兼容层；后续结构变更将通过显式 `schema_version` 和一次性迁移完成。
